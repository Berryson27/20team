# 한큐(HanQ) 보안 근거

> 위조·피싱 QR로부터 사용자를 지키는 QR 검증 서비스.
> 본 문서는 발표 심사 시 **"보안 근거"** 평가 항목을 위한 요약이다.
> 모든 주장은 실제 코드 위치로 검증 가능하다(← 채점 포인트).

---

## 한 줄 요약 (심사위원용)

**한큐의 보안은 "말"이 아니라 "코드"다.**
① 다층 검증 엔진으로 사용자를 방어하고, ② 검증 로직 전체를 서버에 두어 조작을 원천 차단하며, ③ 개인정보는 수집 단계에서 비식별화하고, ④ API 키는 브라우저에 절대 싣지 않는다. 아래 네 축 모두 **파일·함수 단위로 근거를 제시**한다.

---

## 1. 사용자 방어 근거 — 다층 검증 엔진 (S0~S6)

QR 하나를 서로 독립인 여러 신호로 교차 검증한다. 공격자가 한 층을 우회해도 다른 층에 걸린다.

| 단계 | 막는 공격 | 방어 메커니즘 | 코드 근거 |
|---|---|---|---|
| **S1 서명 검증** | QR 바꿔치기·발급번호 사칭 | `HMAC-SHA256(secret, qrId+targetUrl+issuedAt)` 재계산. **`timingSafeEqual`로 타이밍 공격 차단**. 발급기록 없는 우리 포맷 = 즉시 위조 판정 | `functions/src/verify/signature.ts` |
| **S2 리다이렉트 추적** | SSRF·단축URL 우회·프로토콜 다운그레이드 | **사설 IP 차단**(`isPrivateHost`), `MAX_HOPS=3`, HTTPS→HTTP 다운그레이드 감지, 단축 URL 체인·캡차 감지 | `functions/src/verify/redirect.ts` |
| **S3~S6** | 신생 도메인·피싱 페이지 | RDAP 도메인 연령, DOM 구조 분석, 스크린샷 비전(LLM) → score 합산 판정 | `functions/src/verify/engine.ts`, `scoring.ts` |

**핵심 설계 원칙**: 검증·서명·집계는 전부 **서버(Firebase Functions)가 유일한 진실 원천(single source of truth)**. 클라이언트는 결과 표시만 담당 → 판정 로직을 브라우저에서 조작 불가.

## 2. 데이터·프라이버시 근거 — "수집 최소화"

| 원칙 | 구현 | 코드 근거 |
|---|---|---|
| 위치 비식별화 | 정확 좌표는 즉시 **구 단위 행정코드**로 변환 후 폐기(원좌표 미저장) | `verify/index.ts` `toRegion()` |
| URL 원문 미저장 | 스캔 로그에 **해시(`finalUrlHash`)만** 기록 | `verify/index.ts` `scan_logs.add` |
| 최소 권한 접근 | 발급자는 **본인 데이터만** R/W(`ownerUid == auth.uid`), 로그·알림·카운터 쓰기는 **Functions(admin)만**, 그 외 **전부 deny** | `firestore.rules` |

---

## 3. 키·시크릿 근거 — "브라우저에 비밀을 두지 않는다"

| 항목 | 상태 | 근거 |
|---|---|---|
| API 키 브라우저 미노출 | ✅ **검증됨** — 클라이언트 코드·`dist` 빌드 산출물 어디에도 Gemini 키 없음 | `grep` 결과 무유출 |
| Secret Manager 경유 | `GEMINI_API_KEY`·`HANQ_SIGNING_SECRET`을 배포 시 주입, 코드·깃에 부재 | `functions/src/shared/secrets.ts` (`defineSecret`) |
| 시크릿 커밋 차단 | `.env*` 커밋은 훅으로 차단, `.secret.local`은 gitignore(미추적) | `.gitignore`, `functions/.gitignore` |

---

## 4. 남용·가용성 근거 — "공짜로 두들겨 맞지 않는다"

| 위협 | 방어 | 코드 근거 |
|---|---|---|
| LLM 비용 폭탄 | verify **30회/분/IP** 레이트리밋 | `verify/index.ts`, `shared/ratelimit.ts` |
| 신고 스팸(지도 오염) | reports **15회/분/IP** 레이트리밋 | `shared/ratelimit.ts` |
| 방어장치가 서비스 마비 | **Fail-open** — 레이트리밋 저장소 오류 시 통과 | `ratelimit.ts` catch 절 |
| 무권한 접근 | `Authorization: Bearer <idToken>` Firebase Auth 검증 | `shared/http.ts` `requireUid` |

## 심사 발표용 3문장

1. **"우리는 판정 로직을 서버에 두어, 클라이언트에서 위·변조할 수 없게 했습니다."** (SSOT)
2. **"QR 서명은 HMAC-SHA256 + 타이밍세이프 비교로 위조를 즉시 잡고, 리다이렉트 추적은 SSRF·다운그레이드까지 방어합니다."** (다층 엔진)
3. **"위치는 구 단위로 비식별화하고 URL은 해시만 저장하며, API 키는 브라우저에 싣지 않습니다."** (프라이버시·키 관리)
